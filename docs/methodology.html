Map ENOUGH Crosswalk Methodology

Overview

This map overlays six geographic data layers to help the Maryland Governor's Office for Children (GOC) and the Baltimore Vacants Reinvestment Initiative (BVRI) team see where their work intersects. All data is fetched from publicly available, authoritative sources — no proprietary or licensed datasets are required.

The seven layers, with their geographic coverage:

  • ENOUGH grantee tracts (Maryland GOC) — statewide, all 28 active grantees and 111 tracts
  • BVRI Vacants to Value (Baltimore City DHCD) — Baltimore City only
  • DHCD Impact Investment Areas (Baltimore City DHCD) — Baltimore City only
  • NMTC eligibility (US Treasury CDFI Fund) — statewide
  • Designated Opportunity Zones (MD DHCD / Commerce via iMap) — statewide
  • OZ 2.0-eligible tracts (OpportunityZones.com, 2020–2024 ACS) — statewide
  • Maryland Enterprise Zones (MD Dept. of Commerce) — statewide

The default view shows all of Maryland. Use the "Zoom to Baltimore City" button on the map for a closer look at the BVRI overlap.

The full source code, including data-fetch scripts, lives at github.com/Maryland-Governors-Office-for-Children/enough-bvri-map.

Layer 1 — ENOUGH Grantee Tracts

ENOUGH Grantee Tracts — colored by grantee organization

What it shows: All 111 census tracts statewide currently served by 28 active ENOUGH Act grantees, colored by grantee organization.

Source

Internal GOC data, derived from the master ENOUGH grantee list maintained by the Governor's Office for Children. The grantee → tract assignments come from the FY26 ENOUGH grantee tract roster used in the enough-eligibility-changes repo.

Vintage: FY26 active grantees (current as of May 2026)
Geometry: 2020 Census Tracts (TIGER/Line via Maryland Department of Planning ArcGIS)
Refresh cadence: When new grantees are awarded or geographic scope changes

How it's built

Two source files from the enough-eligibility-changes repo are combined:

  • tracts_2026.geojson — statewide tract polygons with poverty / school / eligibility metadata
  • map_filters.json — grantee → tract list, providing the grantee organization name for each tract

The build step joins them and writes docs/data/grantee_tracts.geojson with a grantee_name property on each tract feature, plus docs/data/grantees.json with the master grantee list.

Eligibility note

"Eligible" tracts (i.e. those meeting the ENOUGH Act poverty threshold) and "grantee" tracts are different. A tract is eligible if it meets the ACS child-poverty threshold; a tract is a grantee tract only if a current grantee organization is operating in that geography. Statewide, several hundred tracts are ENOUGH-eligible but only 111 are actively served by current grantees.

BVRI overlap calculation

The "BVRI in Grantee Tracts" stat (currently 565) is computed in the browser via point-in-polygon ray casting: each BVRI property point is tested against each grantee tract polygon; a property is counted as overlapping if it falls within any grantee tract. When a single grantee is selected from the sidebar, the count switches to that grantee's tracts only. The ENOUGH Crosswalk page reports the same figure alongside the per-community breakdown.

Layer 4 — NMTC Eligibility (CDFI Fund)

NMTC Eligibility — off by default; two distress tiers

What it shows: Census tracts statewide that qualify for the New Markets Tax Credit (NMTC) Program, classified by distress severity. Of Maryland's 587 NMTC-eligible tracts, 350 are in Severe Distress and 237 are Distressed; tracts not in the source dataset are not NMTC-eligible.

Source

US Treasury CDFI Fund's authoritative public ArcGIS feature service, distributed via Esri's federal layer manager:

https://services6.arcgis.com/BAJNi3EgCdtQ1BCG/arcgis/
  rest/services/NMTC_Qualified_Tracts_2020/FeatureServer/3

This is the same dataset that PolicyMap and CDFI's own CIMS mapping tool surface. We use it directly to avoid the PolicyMap subscription requirement and to integrate visually with the rest of the map.

Underlying data: 2016–2020 ACS 5-Year Estimates
Tract geometries: 2020 Census Tracts
Eligibility year: CY 2024
Refresh cadence: CDFI Fund updates this dataset when new ACS vintages are released. Run python3 scripts/fetch_nmtc.py to pull the latest.

Distress classification

The CDFI Fund's source service does not store the distress tier as a single field. Instead, the classification is computed from three underlying metrics. We replicate that logic in scripts/fetch_nmtc.py:

TierCriteria (any of)
Severe Distress Income ≤ 60% of benchmark, or poverty rate ≥ 30%, or unemployment ratio ≥ 1.5× national
Distressed Income ≤ 80% of benchmark, or poverty rate ≥ 20%
Eligible Qualifies as a Low-Income Community but not in either tier above
Insufficient Data All three metrics missing
Not Eligible Does not qualify (excluded from the dataset, not shown on map)

The benchmark for the income test is the higher of the statewide median family income or the metropolitan-area median family income (whichever applies based on OMB Metro/Non-metro designation).

Note on PolicyMap

PolicyMap's NMTC layer ("New Markets Tax Credit (NMTC) Program Eligibility, Deep Distress Status, High Migration Rural County Status, Severe Distress Status, and Non-Metropolitan Status, for CY 2024, using 2016-2020 eligibility data") draws on this same underlying CDFI Fund data. Their additional categories ("High Migration Rural County" and "Non-Metropolitan Status") apply only outside metropolitan areas; in Maryland, those would surface in counties like Garrett, Allegany, and the Eastern Shore but not in the Baltimore-Washington metro corridor.

Layer 6 — OZ 2.0-Eligible Tracts

OZ 2.0-Eligible Tracts — off by default

What it shows: The 451 Maryland census tracts that meet the statutory income and/or poverty thresholds to be nominated as Opportunity Zones under the "OZ 2.0" framework. These are eligible tracts, not designated zones: under the 25% statutory cap, Maryland may nominate up to 113 of them, with new designations taking effect January 1, 2027 (the state's nomination window opened in 2026, administered by MD DHCD). Eligibility is derived from the 2020–2024 five-year American Community Survey (ACS) estimates the Census Bureau released on January 29, 2026.

Source

OpportunityZones.com's Maryland state profile (Kingsbury Media LLC), which publishes the eligible-tract list with each tract's median-family-income ratio and poverty rate from its analysis of the 2020–2024 ACS. The list of GEOIDs is read from that page; tract geometry is not scraped — instead each eligible GEOID is joined to the statewide 2020-vintage tract boundaries already used to build the ENOUGH grantee-tract layer, so the polygons are authoritative Census geometry.

Note

Because these tracts share the 2020 Census vintage with the ENOUGH grantee tracts, overlap on the crosswalk uses an exact-GEOID join (like NMTC), not a geometric threshold. This is a forward-looking eligibility layer, so it is deliberately excluded from the "how many statewide programs stack per tract" gap analysis, which counts only currently-designated programs (NMTC, designated OZ, Enterprise Zones).

Grantee-tract overlap

The "Grantee Tracts in Enterprise Zones" stat counts how many of the 111 ENOUGH grantee tracts geographically intersect an Enterprise Zone (Focus Areas are excluded from the count, since they nest inside zones). This overlap — and every figure on the ENOUGH Crosswalk page — is precomputed at build time by scripts/build_crosswalk.py using exact polygon geometry (Shapely). The headline count uses an any-overlap test: a tract is counted if it touches an Enterprise Zone at all, matching the "is any part of this neighborhood in a zone?" framing of the state's Enterprise Zone lookup. The map reads this precomputed figure from docs/data/crosswalk.json so the headline stat, the per-grantee sidebar count, and the crosswalk page always agree. (Current count: 86 grantee tracts touch an Enterprise Zone, across 21 communities.)

A stricter alternative: under a test requiring at least 5% of a tract's area to fall inside a zone, 71 grantee tracts count. The 15-tract difference is entirely boundary slivers — tracts that only clip a zone's edge (all under 5% of tract area; the smallest is 0.5%). The crosswalk page footnotes this 71 figure alongside the 86 headline. Note that Opportunity Zones and the DHCD areas still use the 5%-area test, because for Opportunity Zones the 5% threshold is validated against an exact-GEOID join (both reproduce 38 tracts); Enterprise Zones have no tract-based ground truth to validate against, so the more inclusive any-overlap count is used as the headline.

The ENOUGH Crosswalk page

The ENOUGH Crosswalk page answers, for each non-grantee layer, how many ENOUGH communities and grantee tracts overlap it — plus a "stacking" view of how many statewide incentive programs coincide in each tract. All of its figures are precomputed at build time by scripts/build_crosswalk.py (Python + Shapely) and written to docs/data/crosswalk.json, which both the crosswalk page and the map read. Computing overlaps once, server-side, keeps every page consistent and avoids re-deriving geometry in the browser.

Because NMTC uses an exact-GEOID join while the polygon layers use a 5% area threshold, the two methods aren't identical — but they agree where they can be compared. Applying the 5% geometric method to Opportunity Zones yields 38 grantee tracts, exactly matching the OZ exact-GEOID join (38). That agreement is what justifies the 5% cutoff: it's low enough to catch real overlaps and high enough to drop boundary slivers, and it reproduces an independent count rather than being tuned to a desired answer.

Reading the community vs. tract numbers

A community is counted as overlapping a layer if any one of its tracts does. This is a deliberately generous "is this tool available anywhere in this community?" measure — useful, but it can make coverage look higher than the on-the-ground footprint (a 10-tract grantee with one tract in a zone counts the same as one fully inside it). That's why the page always shows the grantee-tract share alongside the community share: the tract number is the stricter measure of how much of a community a program actually reaches. Three tracts are served by two grantees each, so per-community counts in the breakdown tables can sum to slightly more than a layer's tract total; the layer's headline tract count is de-duplicated.

Stacking and gaps

The crosswalk page's final section counts, for each grantee tract, how many of the three statewide incentive programs (NMTC, Opportunity Zones, Enterprise Zones) overlap it. The Baltimore-only layers are excluded from this count so a rural grantee tract isn't penalized for lacking a Baltimore vacant-property program. Tracts in zero statewide program are surfaced explicitly — these are the places where ENOUGH is currently the only place-based tool and the clearest candidates for new investment or advocacy.

Keeping the data fresh

crosswalk.json is a committed artifact, so it can drift from its source layers if one is refreshed without rebuilding. To guard against that, the build script stamps a source_hash (a SHA-256 of all input files) into the output, and python scripts/build_crosswalk.py --check recomputes that hash and exits with an error if the committed JSON is stale. Run the check before sharing the site externally; if it reports "STALE," rerun the build and commit the refreshed crosswalk.json.

How to refresh data

From the project root:

# Refresh BVRI data (Vacants to Value + Investment Areas)
python3 scripts/fetch_bvri.py

# Refresh NMTC eligibility
python3 scripts/fetch_nmtc.py

# Refresh designated Opportunity Zones
python3 scripts/fetch_oz.py

# Refresh OZ 2.0-eligible tracts (also writes the rural flag onto designated OZs)
python3 scripts/fetch_oz2.py

# Refresh Maryland Enterprise Zones
python3 scripts/fetch_ez.py

# Refresh ENOUGH grantee tracts (after enough-eligibility-changes updates)
# See CLAUDE.md for the inline Python snippet

# Rebuild the ENOUGH Crosswalk data (needs shapely — see requirements-crosswalk.txt)
python3 -m venv .venv-geo
.venv-geo/bin/pip install -r scripts/requirements-crosswalk.txt
.venv-geo/bin/python scripts/build_crosswalk.py
# Verify it's in sync before sharing:
.venv-geo/bin/python scripts/build_crosswalk.py --check

# Then commit and push
git add docs/data/
git commit -m "Refresh data"
git push

GitHub Pages auto-deploys from main branch docs/ within ~60 seconds.

Caveats and limits

  • Tract vintages: All four layers use 2020 Census Tracts. ENOUGH eligibility uses 2024 ACS 5-Year (the latest available); NMTC uses 2016–2020 ACS (CDFI Fund's current eligibility cycle). The two ACS vintages don't align perfectly, but tract-level geographic boundaries are the same.
  • Point-in-polygon accuracy: The BVRI overlap counts use simple ray-casting on tract polygons. Properties exactly on tract boundaries can occasionally be misclassified; in practice this affects <1% of points.
  • BVRI dataset scope: The "Vacants to Value" open bid list (~1,192 properties) is one of several Baltimore vacant-property datasets. It does not include vacant building notices, demolitions completed, or properties already in receivership. Those are separate layers in the same DHCD feature server (Layers 0, 1, 2, 4, 5) if needed.
  • NMTC tier coverage: The CDFI Fund's authoritative service excludes ineligible tracts entirely (rather than including them with a "Not Eligible" classification). So a tract with no NMTC-layer fill is simply not in the dataset; we don't render the "Not Eligible" or "Insufficient Data" tiers because they're empty for Baltimore City.
